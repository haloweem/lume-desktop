# OpenCC weather place-name data

The original Lume source depends on `opencc-js` 1.4.2 and calls
`Converter({ from: 't', to: 'cn' })` only when a place name contains one of its
listed Chinese characters. The native weather resolver preserves the converter,
including phrases and compatibility ideographs, but applies it unconditionally
as requested by the user on 2026-09-26: all displayed text must use Simplified
Chinese, including names skipped by the original trigger.

`core/weather/weather_places_data.inc` is generated by
`tools/generate-weather-place-data.mjs` from these files in the original
`src/vscode-windhawk/node_modules/opencc-js/dist/esm-lib/dict`:

Dictionary data is derived from the nk2028 project's opencc-data and is
distributed under Apache-2.0. The license is included in
`opencc-data-LICENSE.txt`; upstream package notices are retained in
`opencc-js-THIRD_PARTY_LICENSES.md` and `opencc-js-LICENSE.txt`.

Changes: dictionaries were merged respecting phrase priority, sorted by UTF-8
key, and packed into static UTF-8 strings plus offset/length records. Native
conversion uses longest-prefix lookup over read-only tables. No OpenCC
JavaScript runtime, heap-allocated trie, or additional background thread is
included. The generator's `--check --verify-native <test executable>` compares
the native output with the original JavaScript converter at build/test time.
